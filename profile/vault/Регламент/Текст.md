# РЕГЛАМЕНТ
## Управления Информационными Технологиями регионального отделения по Челябинской области Партии «Рассвет» (УИТ)
**Редакция 4 от 20.05.2026**

### 1. Общие положения

1.1. Управление Информационными Технологиями регионального отделения по Челябинской области Партии «Рассвет» (далее — УИТ) является подразделением Челябинского регионального отделения Партии (далее — отделение Партии), ответственным за стратегическое и оперативное развитие ИТ-инфраструктуры отделения Партии.

1.2. УИТ действует на основании Устава Партии и настоящего Регламента.

1.3. Основные задачи УИТ:
- обеспечение цифровой инфраструктуры отделения Партии,
- сопровождение внутренних процессов в формате open-source,
- внедрение инструментов прозрачной и минималистичной организации цифровой работы.

### 2. Структура УИТ

2.1. В состав УИТ входят:
- **Куратор УИТ** (входит в Челябинское региональное отделение по должности),
- **Проектные группы** (по 2–3 разработчика на проект),
- **Кураторы проектных групп** по направлениям:
  - серверная разработка,
  - разработка интерфейсов,
  - децентрализованных вычислений,
  - безопасность,
  - кадры,
- **Внештатные сотрудники проектных групп** (внешние контрибьюторы).

2.2. Каждый проект имеет свою группу со своим именем и Куратора проектной группы, который:
- соединяет техническое видение команды с задачами от Куратора УИТа,
- организует планирование (Kanban, диаграммы Ганта, TOGAF),
- доводит инициативы разработчиков до Куратора УИТ,
- реализует инструкции сверху через нарезку задач и эпиков.

2.3. **Комитет отдела** — коллегиальный орган управления отделом, который:
- созывается регулярно или при необходимости Куратором УИТ,
- фасилитируется Куратором УИТ,
- включает в себя всех Кураторов проектных групп соответствующего отдела,
- рассматривает вопросы координации работы между проектными группами или внутри проектных групп,
- обсуждает стратегические инициативы отдела,
- принимает решения по межпроектным задачам и ресурсам.

### 3. Принципы работы

3.1. **Минимализм в инструментах:**
- GitHub — единая платформа для кода, документации, тикетов, вики,
- Google Meet и Loom AI — для встреч и протоколов,
- Один Telegram-чат — только для экстренной связи, автоудаление сообщений каждые 4 дня.

3.2. **Документированность:**
- Перед выполнением задачи каждый разработчик пишет краткое описание, как он её будет выполнять.
- Все митинги и статусы оформляются в виде открытых повесток и протоколов.

3.3. **Open-source:**
- Все проекты и репозитории УИТ по-умолчанию публичны.
- Каждый проект сопровождается: README, руководствами, CI/CD, кодексом поведения, описанием безопасности хранения секретов, если таковые применяются.

3.4. **Малые команды:**
- На один проект — максимум 3 человека.
- Никогда не формируются команды из двух Junior-разработчиков.
- При наличии только одного Junior — проект приостанавливается до донабора.

### 4. Роли и обязанности

4.1. Куратор УИТ:
- ведёт реестр сотрудников и контрибьюторов,
- отвечает на инициативы разработчиков поднятые на комитетах отделов,
- формирует/распускает проектные группы,
- составляет и публикует повестки и протоколы работы,
- издаёт инструкции обязательные для исполнения для проектных групп по итогам запросов регламентных органов Партии или по собственному решению,
- анализирует состояние дел в управлении по создаваемой на каждом этапе работ документации.

4.2. Кураторы проектных групп:
- находятся в Партии,
- собирают статусы и отчётность команды,
- ведут миты (планинг, дейлики, ретро) - если необходимо,
- координируют реализацию задач через Kanban и эпики,
- взаимодействуют с Куратором УИТ по всем инициативам и запросам,
- транслируют инструкции Куратора УИТ в технические задачи.

4.3. Сотрудники проектных групп (разработчики):
- находятся в Партии,
- пишут код, тесты и документацию,
- соблюдают правила open-source культуры,
- участвуют в планировании и ретроспективах.

4.4. Внештатные сотрудники проектных групп:
- внепартийные разработчики, участвующие в проектах УИТ,
- работают через публичные GitHub-репозитории в формате open-source контрибьюций,
- не имеют доступа к внутренним партийным коммуникациям и документам,
- взаимодействуют только через открытые каналы (GitHub Issues, Pull Requests, публичные обсуждения),
- их участие координируется Куратором проектной группы,
- могут быть приглашены к участию в открытых технических обсуждениях проектов,
- не участвуют в принятии стратегических решений УИТ.

### 5. Передача полномочий Куратора УИТ

5.1. Передача полномочий Куратора УИТ осуществляется в следующих случаях:
- смена регионального отделения Партии,
- добровольное сложение полномочий Куратора УИТ,
- решение Секретаря Челябинского регионального отделения Партии об отзыве полномочий Куратора УИТ.

5.2. При передаче полномочий:
- все административные доступы и права подписи передаются преемнику через подпись PGP текущего Куратора УИТ,
- личная PGP-подпись текущего Куратора УИТ отзывается из всех систем и официально аннулируется,
- приватный ключ Куратора УИТ безопасно передаётся преемнику в соответствии с протоколами безопасности,
- все активные проекты и обязательства документируются и передаются новому Куратору УИТ.

5.3. Процедура передачи полномочий:
- уходящий Куратор УИТ готовит полный отчёт о состоянии всех проектов и систем,
- совместно с преемником составляется акт приёма-передачи полномочий,
- передача PGP-ключей и доступов происходит в присутствии представителя Секретаря Челябинского отделения Партии,
- права администратора GitHub организации УИТ передаются новому Куратору УИТ,
- после завершения передачи публикуется официальное уведомление всем участникам УИТ.

5.4. Переходный период:
- в случае необходимости может быть установлен переходный период до 14 дней,
- в течение переходного периода оба Куратора работают совместно для обеспечения непрерывности процессов,
- все ключевые решения в переходный период принимаются совместно или утверждаются Советом Челябинского регионального отделения Партии.

### 6. Кадровые положения

6.1. Приоритет найма: Senior > Middle > Junior.

6.2. Все участники распределяются по уровням и направлениям через согласование с Куратором УИТ через решение соответствующего Комитета отдела Кадров.

6.3. Комитет отдела Кадров приостанавливает участие Junior-разработчика без поддержки более опытных коллег.

### 8. Стегано-печати

8.1. **Назначение стегано-печатей:**
- стегано-печати используются для подтверждения подлинности официальных документов УИТ,
- стегано-печати представляют собой стеганографические метки, зашифрованные по алгоритму AES256,
- каждый сотрудник УИТ имеет право устанавливать стегано-печати на документы в рамках своих полномочий.

8.2. **Установка стегано-печатей:**
- стегано-печать представляет собой изображение в формате PNG, содержащее стеганографическую метку,
- стеганографическая метка содержит зашифрованную по алгоритму AES256 информацию о документе, авторе и дате,
- каждый сотрудник выбирает себе уникальный пароль AES256 для своих стегано-печатей,
- пароли публикуются в открытом доступе в разделе PGP публичных ключей,
- стегано-печать размещается в конце официального документа в виде изображения со ссылкой,
- стегано-печать устанавливается на финальную версию документа перед его публикацией,
- формат размещения в Markdown-документах: `![Имя должности в УИТ - ФИО](./Стегано_печать_Должность_Документ.png)`.

8.3. **Проверка стегано-печатей:**
- любой участник может проверить подлинность документа путём извлечения стегано-печати,
- расшифровка осуществляется с использованием публично доступного пароля AES256,
- успешная расшифровка подтверждает авторство и неизменность документа,
- при обнаружении несоответствия стегано-печати документ считается неподлинным.

8.4. **Смена паролей стегано-печатей:**
- при смене должности или выходе сотрудника из УИТ его пароль стегано-печати аннулируется,
- все предыдущие пароли сохраняются в архиве для возможности проверки исторических документов,
- новый пароль генерируется и публикуется Куратором УИТ,
- при смене Куратора УИТ обновляются пароли всех активных сотрудников.

8.5. **Ответственность:**
- каждый сотрудник несёт ответственность за конфиденциальность приватной части своих стегано-печатей,
- компрометация приватной части стегано-печати должна быть незамедлительно сообщена Куратору УИТ,
- злоупотребление стегано-печатями является основанием для увольнения из УИТ.

### 9. Порядок внесения изменений

Изменения в Регламент УИТ вносятся:
- по инициативе Куратора УИТ,
- по решению Секретаря Челябинского регионального отделения Партии,
- по решению Совета Челябинского регионального отделения Партии,
- по предложениям Кураторов проектных групп, одобренных Куратором УИТ.
