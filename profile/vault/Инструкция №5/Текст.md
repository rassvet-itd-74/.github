# Управление ИТ 
регионального отделения по Челябинской области Партии "Рассвет" (УИТ)
### Куратор УИТ: Олег Александрович Бедрин

#### Проектная группа "Шамир" - Отдел безопасности

## Регламент процедуры обмена чувствительными данными посредством PGP-шифрования для Регионального Совета отделения

1) Принять настоящий регламент, введённый от имени Проектной группы "Шамир" в соответствии с её мандатом, закреплённым в Инструкции №3 (п. 6.4): *«создание инструкций по созданию, обмену и хранению секретов отделения Партии (приватных ключей, доступов и проч.)»*.
2) Использовать в качестве допустимого формата передачи `.asc`-файл, зашифрованный с применением публичных PGP-ключей получателей, хранящихся в директории `/profile/pgp/soviet/keys` настоящего репозитория.

3) Зарегистрировать желающего члена регионального отделения и опубликовать его публичный ключ.
   1) Каждому члену регионального отделения, участвующему в обмене чувствительными данными, сгенерировать ключевую пару PGP (см. [руководство по Kleopatra](./Руководство-Kleopatra.md)) и передать публичный ключ (файл `.asc`) Куратору УИТ или Куратору Проектной группы "Шамир".
   2) Ответственному сотруднику Проектной группы "Шамир" опубликовать полученный ключ в директории `/profile/pgp/soviet/keys` репозитория с коммитом вида: `Добавлен публичный ключ [Имя]`.
   3) Члену регионального отделения, чей ключ опубликован, передать его **отпечаток** (fingerprint) остальным членам вне основного канала связи (в Telegram чате отделения) для последующей верификации.

4) Получить актуальные публичные ключи получателей перед отправкой.
   1) Перейти в директорию `profile/pgp/soviet/keys/` настоящего репозитория.
   2) Скачать `.asc`-файлы всех предполагаемых получателей.
   3) Проверить подлинность каждого ключа: сверить отпечаток с тем, что был передан владельцем ключа вне основного канала связи.

5) Импортировать публичные ключи в Kleopatra.
   1) Открыть **Kleopatra**.
   2) Нажать **Import...** (Импорт) и выбрать скачанный файл `.asc`.
   3) Повторить для каждого ключа получателя.
   4) Для каждого импортированного ключа выполнить сертификацию: щёлкнуть правой кнопкой → **Certify...** (Сертифицировать), убедившись в совпадении отпечатка.

6) Зашифровать файл с чувствительными данными.
   1) В Kleopatra нажать **Sign/Encrypt Files...**.
   2) Выбрать целевой файл (`.txt` или иной формат).
   3) В открывшемся диалоге установить флаг **Encrypt** (Зашифровать) и флаг **Sign** (Подпись) — подпись обязательна для верификации отправителя получателем.
   4) Нажать **Next** и в списке получателей добавить публичные ключи **всех** предполагаемых получателей.
   5) Нажать **Encrypt** — Kleopatra создаст файл `.asc` в той же директории, что и исходный файл.

7) Передать зашифрованный файл.
   1) Передать полученный файл `.asc` получателям через репозиторий, мессенджер или иной доступный канал — публиковать его в открытом доступе безопасно, поскольку без приватных ключей получателей расшифровка невозможна.
   2) Хранить исходный файл с чувствительными данными в защищённом месте либо удалить его после шифрования; к передаче в открытом виде он не предназначен.

8)  Расшифровать полученный файл.
    1) Открыть **Kleopatra** и нажать **Decrypt/Verify...** (Расшифровать/Проверить).
    2) Выбрать полученный файл `.asc`.
    3) Ввести парольную фразу приватного ключа при запросе.
    4) Убедиться в том, что подпись отправителя, отображённая Kleopatra, принадлежит ожидаемому отправителю.

9)  При компрометации или утрате ключа выполнить следующее.
    1) Незамедлительно уведомить Куратора УИТ и Куратора Проектной группы "Шамир".
    2) Удалить скомпрометированный публичный ключ из Kleopatra.
    3) Сгенерировать новую ключевую пару и повторить процедуру п. 5 настоящей инструкции.
