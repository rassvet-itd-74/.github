# Приложение к Инструкции №4 "Управление ИТ регионального отделения по Челябинской области"

## Групповое PGP-шифрование с Kleopatra и GitHub

Данное руководство описывает, как группа участников может обмениваться зашифрованными сообщениями с помощью PGP-шифрования и Kleopatra. Один **выделенный человек** (хранитель ключей) управляет репозиторием на GitHub и занимается распространением ключей. Все остальные участники должны только установить Kleopatra.

## Роли

| Роль | Обязанности |
|---|---|
| **Выделенный человек** | Управляет репозиторием на GitHub, собирает публичные ключи, публикует зашифрованные сообщения |
| **Участник** | Генерирует ключевую пару в Kleopatra, отправляет публичный ключ выделенному человеку, расшифровывает полученные сообщения |
| **Отправитель** | Любой участник, желающий отправить сообщение группе |

## Предварительные требования

- **Все участники:** установить [Kleopatra](https://gpg4win.de/download.html) (входит в состав пакета Gpg4win для Windows)

## Часть 1: Каждый участник — генерация и передача ключа

Выполните эти шаги один раз перед началом обмена сообщениями.

### Шаг 1 — Генерация ключевой пары

1. Откройте **Kleopatra**
2. Нажмите **New Key Pair** (Новая ключевая пара)
3. Выберите **Create a personal OpenPGP key pair**
4. Введите своё имя и адрес электронной почты, нажмите **Next**
5. Задайте надёжную парольную фразу — она защищает ваш приватный ключ
6. Нажмите **Create**, дождитесь завершения генерации, затем нажмите **Finish**

Ваша ключевая пара появится в списке ключей Kleopatra.

### Шаг 2 — Экспорт публичного ключа

1. Щёлкните правой кнопкой мыши по своему ключу в списке
2. Выберите **Export...** (Экспорт)
3. Сохраните файл как `вашеимя.asc` (например, `alice.asc`)

### Шаг 3 — Отправка публичного ключа выделенному человеку

Отправьте экспортированный файл `вашеимя.asc` выделенному человеку любым доступным способом (электронная почта, мессенджер и т.д.). Он самостоятельно опубликует ваш ключ в репозитории на GitHub.

### Шаг 4 — Проверка отпечатка ключа вне основного канала

Чтобы убедиться, что ваш ключ не был подменён, передайте **отпечаток ключа** другим участникам группы через надёжный сторонний канал (личное сообщение, телефонный звонок или при личной встрече).

Как найти отпечаток в Kleopatra:
1. Дважды щёлкните по своему ключу в списке
2. Отпечаток отображается в верхней части панели сведений о ключе
3. Передайте эту строку участникам — они должны убедиться, что она совпадает после импорта вашего ключа

## Часть 2: Выделенный человек — управление ключами и сообщениями на GitHub

### Получение и публикация публичных ключей

Когда участник присылает вам свой файл `.asc`:
1. Загрузите его в папку `/profile/pgp/soviet/keys/` репозитория на GitHub
2. Сделайте коммит с сообщением, например: `Добавлен публичный ключ [Имя]`

Ключ теперь доступен всем участникам группы для скачивания.

### Публикация зашифрованных сообщений

Когда отправитель передаёт вам зашифрованный файл сообщения:
1. Загрузите файл `.asc` в папку `/profile/pgp/soviet/messages/` репозитория
2. Сделайте коммит с описательным сообщением, например: `Добавлено сообщение [номер сообщения]`

## Часть 3: Отправитель — импорт ключей и шифрование сообщения

Любой участник, желающий отправить сообщение группе, выполняет следующие шаги.

### Шаг 1 — Загрузка всех публичных ключей

1. Перейдите в папку `/profile/pgp/soviet/keys/` общего репозитория на GitHub
2. Скачайте все файлы `.asc` (по одному на каждого участника)

### Шаг 2 — Импорт ключей в Kleopatra

Для каждого скачанного файла `.asc`:
1. Откройте **Kleopatra** и нажмите **Import...** (Импорт)
2. Выберите файл `.asc` — ключ появится в вашей связке ключей
3. Повторите для каждого участника

### Шаг 3 — (Необязательно) Сертификация ключей

Чтобы пометить импортированные ключи как доверенные:
1. Щёлкните правой кнопкой по ключу → **Certify...** (Сертифицировать)
2. Убедитесь, что отпечаток совпадает с тем, что участник передал вам вне основного канала
3. Завершите сертификацию

### Шаг 4 — Шифрование простого текстового сообщения

1. Откройте **Kleopatra** и перейдите на вкладку **Notepad** (Блокнот)
2. Введите или вставьте текст секретного сообщения
3. Нажмите **Encrypt Notepad** (Зашифровать)
4. В диалоге выбора получателей **добавьте ключи всех участников**
5. Нажмите **Encrypt**
6. Зашифрованный текст появится в блокноте — он начинается с `-----BEGIN PGP MESSAGE-----`
7. Нажмите **Save As...** и сохраните файл как `message_[какой-нибудь комментарий уточняющий на английском языке].asc`

### Шаг 5 — Передача зашифрованного сообщения выделенному человеку

Отправьте файл `message_[какой-нибудь комментарий уточняющий на английском языке].asc` выделенному человеку — он загрузит его в папку `/profile/pgp/soviet/messages/` на GitHub.

## Часть 4: Каждый участник — расшифровка сообщения

Когда в папке `/profile/pgp/soviet/messages/` появляется новое сообщение:

### Шаг 1 — Загрузка зашифрованного сообщения

1. Перейдите в папку `/profile/pgp/soviet/messages/` репозитория на GitHub
2. Скачайте последний файл `message_XXX.asc`

### Шаг 2 — Расшифровка в Kleopatra

1. Откройте **Kleopatra** и нажмите **Decrypt/Verify...** (Расшифровать/Проверить)
2. Выберите скачанный файл `.asc`
3. Введите **парольную фразу** приватного ключа при появлении запроса
4. Kleopatra отобразит расшифрованный текст

Если ваш ключ был указан среди получателей, расшифровка пройдёт успешно. В противном случае Kleopatra сообщит об отсутствии подходящего секретного ключа.

## Замечания по безопасности

| Аспект | Рекомендация |
|---|---|
| **Безопасность приватного ключа** | Никогда не передавайте приватный ключ никому, включая выделенного человека. Передаётся только файл `.asc` с публичным ключом. |
| **Надёжность парольной фразы** | Используйте длинную уникальную парольную фразу для приватного ключа. |
| **Подлинность ключей** | Всегда проверяйте отпечатки ключей вне основного канала перед тем, как доверять импортированному ключу. |
| **Компрометация ключа** | Если приватный ключ утерян или скомпрометирован, сгенерируйте новую ключевую пару, отправьте новый публичный ключ выделенному человеку и уведомите группу. |
| **Безопасность публикации шифртекста** | Зашифрованные файлы `.asc` нельзя прочитать без приватных ключей — их публикация на GitHub является намеренной и безопасной. |
